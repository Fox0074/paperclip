# Изолированная проверка взаимодействия команды — не запуск продукта

Цель: проверить путь от коммерческой гипотезы до локального проверенного изменения и отчёта. Все данные ниже — синтетический учебный набор; не делать вывод о реальном спросе или выручке. Не искать клиентов, не публиковать, не отправлять сообщения людям, не покупать ничего, не менять production. Разрешены вызовы существующей модели в утверждённых бюджетах, Paperclip API и работа только в /workspace/team-validation/.

Учебная гипотеза: небольшим студиям нужен калькулятор стоимости пакета работ. Фиктивные входные наблюдения: F1 — студия A считает 3 одинаковые услуги по 199 центов; F2 — студия B хочет 0 услуг; F3 — студия C ошибочно вводит отрицательное количество. Источник всех F — этот учебный набор, дата теста. Это не отзывы настоящих пользователей. Готовность платить неизвестна; решение о реальной разработке требует проверки рынка отдельно.

Все передачи выполняются в рамках ОДНОЙ этой задачи, через штатные checkout, комментарии и reassign. Не создавать дочерние задачи и лишние исследования. Контекст — описание и комментарии этой задачи; артефакты — локальная папка и прикреплённые work products. После своей стадии добавь комментарий с маркером `TEAM-STAGE-N: PASS` и конкретными доказательствами, затем PATCH задачи: status=todo, assigneeAgentId=следующий агент, с краткой передачей результата. Заверши свой запуск сразу после передачи. Одновременных исполнителей не должно быть. Если не можешь передать, запиши точный ответ API и blocker, не имитируй успех. Не объявляй всю проверку успешной, пока QA не выполнил тесты.

Стадии (один агент выполняет только текущую назначенную стадию; определяй её по последнему завершённому маркеру):

0. CEO: зафиксировать учебную цель, запрет внешних действий, критерии: корректный расчёт, независимое QA, прослеживаемый отчёт. Передать CPO.
1. CPO: сформулировать два исследовательских вопроса по F1–F3 и минимальный результат. Передать Researcher.
2. Researcher: разобрать F1–F3, отметить синтетичность и неизвестную готовность платить, риск ошибочного ввода и отсутствие рыночных доказательств. Передать CPO.
3. CPO: написать проверяемое требование: pure JS функция quote(units, priceCents) -> целое число центов; аргументы неотрицательные безопасные целые; 3*199=597, 0*199=0; отрицательные, дробные, нечисловые и переполнение результата отклоняются. Передать CTO.
4. CTO: выбрать минимальную реализацию на Node.js без зависимостей и сервера, файлы /workspace/team-validation/quote.mjs и quote.test.mjs; определить план проверки и назначить Developer.
5. Developer: реализовать функцию и тесты средствами node:test/assert, фактически выполнить `node --test /workspace/team-validation/quote.test.mjs`, прикрепить файлы/результат проверки через Paperclip artifacts/work products. Передать QA.
6. QA: независимо прочитать требование и код, фактически повторить тесты и отдельно проверить 3*199, ноль, отрицательные/дробные/нечисловые входы и переполнение; указать вывод и фактическое число тестов. При дефекте дать воспроизводимый blocker; не переписывать продуктовый код самовольно. При успехе передать COO.
7. COO: проверить наличие всех предыдущих маркеров, передач, артефактов, результатов QA; зафиксировать итоговое состояние, отделить выполненное от ограничений. Передать CEO.
8. CEO: итоговый отчёт с ссылками на артефакты и QA; явно указать: коммерческий спрос не проверен, продукта в production нет, выручки нет; завершить только эту тестовую задачу status=done. Предложить владельцу отдельную следующую коммерческую цель, но не запускать её.

У каждой передачи укажи цель следующей стадии, контекст/ссылки, ожидаемый результат, критерии готовности, normal priority, текущий лимит задачи из настроек исполнителя и таймаут 15 минут. При ошибке не более двух обоснованных повторов. Общий бюджет компании $50/месяц; его нельзя увеличивать.
